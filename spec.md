# FBIM Specification

> Japanese version: [spec.ja.md](spec.ja.md)

---

## Directory structure

```
issues/
  README.md           Issue list (auto-generated by fbim)
  N-name.md           Open or pending issues
  done/
    N-name.md         Closed issues
```

## File naming

```
N-short-name.md
```

- `N`: Plain positive integer, no zero-padding. Assigned by `fbim create` as max existing number + 1.
- `short-name`: Kebab-case short description (ASCII alphanumeric and hyphens only, up to 30 characters).

**The ID lives only in the filename — not in frontmatter or body.**

**Backward compatibility**: Legacy zero-padded IDs (`0042-*.md`, `00042-*.md`) are supported. All tools read them; new issues are always created without padding.

## Frontmatter

```markdown
---
status: open
priority: high|medium|low
area: area-name (e.g. core, cli, docs)
labels: []
---
```

Frontmatter is optional. When absent, defaults are applied: `status: open`, `priority: medium`, `area: ""`.

**status values**

| Value | Meaning |
|---|---|
| `open` | Needs action. |
| `pending` | Blocked or deferred. |
| `done` | Closed (moved to `done/`). |

**priority values**

| Value | Meaning |
|---|---|
| `high` | Needs immediate attention. |
| `medium` | Needs action but not urgent. |
| `low` | Suggestion or improvement opportunity. |

## Title

**The title is extracted from the first `# Heading` line in the body — not from frontmatter.**

Falls back to the file stem if no heading is found.

## Issue file template

```markdown
---
status: open
priority: medium
area: area-name
labels: []
---

# Title

Brief description of what needs to be done.
```

## `.fbim.yml`

Optional configuration file placed in the project root.

```yaml
issues_dir: issues    # default: issues

area_order:           # display order in the list (alphabetical if omitted)
  - backend
  - frontend
  - misc

area_labels:          # display names for areas (area name used as-is if omitted)
  backend: "Backend"
  frontend: "Frontend"
  misc: "Other"
```

## Project root discovery

When any `fbim` command runs, it walks up from the current directory toward the filesystem root, stopping at the first directory that matches either condition:

1. A `.fbim.yml` file is present — the `issues_dir` value is used as the issues directory.
2. An `issues/` subdirectory is present.

Falls back to `issues/` relative to the current directory if nothing is found.
