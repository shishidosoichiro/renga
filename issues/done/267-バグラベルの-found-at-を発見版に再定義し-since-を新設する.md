# バグラベルの found_at を発見版に再定義し since を新設する

## 問題

`.claude/rules/issue-management.md` の `found_at:X.Y.Z` は、「そのバージョンから存在していたバグ」を指す。この定義では、バグを見つけた版と作り込んだ版を区別できない。

## 案

次のように2つのラベルに分ける。

| ラベル | 意味 | 付けるとき |
|---|---|---|
| `found_at:vX.Y.Z` | バグを見つけた版 | 起票時 |
| `since:vX.Y.Z` | バグを作り込んだ版 | 調査で分かったら後から付ける |

分ける利点: リリースノートに「どの版で入った regression か」を書ける。発見時に分からない情報を、推測で埋めずに済む。

## 吟味すべき論点

- Renga の規模で、2つのラベルを使い分ける価値があるか
- 既存の `found_at:` ラベルの意味が変わる。既存の issue を読み替えるか、移行するか
- `/commit` スキルのコミット戦略（`found_in_impl` か `fix:` か）との対応

この変更は `.claude/` を変えるので、retro → self-improve を通す。


## 判断（2026-10-07）

案のとおり2つに分ける。ただし版の書式は既存に合わせて `v` を付けない（`found_at:0.17.0`）。

### 観測: `found_at` はすでに2つの意味で使われている

起票時点の最新タグと `found_at` の値を比べると、意味が混在している。

- 作り込んだ版として使った例: #242・#249（起票時 v0.16.0、`found_at:0.1.0`）、#214（v0.15.0、`found_at:0.1.0`）、#176（v0.11.0、`found_at:0.2.0`）
- 見つけた版として使った例: #275（起票時 v0.17.0、`found_at:0.17.0`）。`validate` は 0.5.0 で入っている（CHANGELOG）ので、作り込んだ版ではない。#269・#272 も同じ日に `found_at:0.17.0` で起票された

ルールは `.claude/rules/issue-management.md` にあり、`paths: issues/**/*.md` で読み込まれる。Claude Code の公式文書によれば、paths 付きの rules は Read・Write・Edit で該当ファイルに触れたときに読み込まれる。`renga create --label` で起票するときは読み込まれないので、エージェントは自然な解釈（今の版）で付けていたと考えられる。

### 論点への答え

1. **使い分ける価値**: ある。分けないと、上の観測のとおり1つのラベルが2つの意味を持ち続ける。`found_at` は起票時に機械的に決まる（最新タグ。利用者からの報告なら利用者の `renga --version`）。`since` は調査が要るので、分かったときだけ付ける。推測で埋めない。どちらも付ける手間は小さい
2. **既存の `found_at:` の扱い**: 移行しない。起票時のタグと同じ値を持つ issue（#168・#188・#151・#223 など）は、どちらの意味か機械的に判別できない。未完了で該当するのは #275 だけで、新しい定義に合っている。読み手のために、rules に「#267 より前の `found_at` は両方の意味で使われている」と一文を残した
3. **`/commit` のコミット戦略との対応**: 戦略を決めるのはラベルではなく「バグを入れたコードがリリース済みか」である。今回の実装で入った → `found_in_impl`。前タグ以降の別コミット → fixup。リリース済み → `fix:` に `found_at` を付け、分かれば `since` も付ける。`since` は戦略を変えない

### 出口（self-improve の3つの問い）

- 既存のルールは読まれていたか: 起票経路（`renga create`）では読み込まれない。そのため、起票する工程の `/commit` スキル（手順 4）にも定義を書いた
- 機械で判定できるか: `found_at` は最新タグで決まるが、hook で自動付与するほどの頻度ではない。`since` は調査が要るので機械化できない
- 誰が、いつ要るか: バグを issue 化するとき（`/commit`）と、issue を読むとき（rules）。CLAUDE.md には置かない

### 見送り

- `found_at` の自動付与（`.renga.yml` の既定ラベルや hook）: 既定ラベルは全 issue に付くので使えない。`found_at` が付け忘れられる retro が出たら再検討する
- 既存 issue の `since` への移行: 上記のとおり判別できないため
