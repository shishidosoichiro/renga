# retro: コミット前レビューとバグ発生源の判定を実装フローに追加

## 起きたこと

レビューをコミット後に行ったため、指摘されたバグを全て `fix:` コミットとして入れてしまった。
しかしそのバグの大半は「今回の実装で入ったバグ」であり、ユーザーが経験したことのないバグだった。
CHANGELOG に並ぶと「0.9.0 の feature で入ったバグを 0.9.0 で直した」という意味のない記述になる。

## 正しいフロー

**コミット前にレビューを行い、指摘を2種類に分類する：**

1. **今回の実装で入ったバグ** → コミット前に修正し feature コミットに含める（CHANGELOG に出さない）
2. **以前のバージョンから存在していたバグ** → コミット後に別の `fix:` コミットで修正（CHANGELOG に出す）

判定基準：「このバグは今回変更したコードに由来するか？」。新規追加ファイルや今回変更した箇所に起因するなら (1)、それ以外は (2)。

## CLAUDE.md への反映

実装フローを以下に変更する：

1. 実装 + テスト追加
2. カバレッジ確認
3. **コミット前に** レビューを受ける
4. 指摘を分類する：「今回の実装で入ったバグ」か「以前からあったバグ」か
5. 今回の実装で入ったバグ → コミット前に修正（feature コミットに含める）
6. コミット（feature + 同一実装内バグ修正をまとめて）
7. 以前からあったバグ → コミット後に別の `fix:` コミットで修正
8. issue を close する
