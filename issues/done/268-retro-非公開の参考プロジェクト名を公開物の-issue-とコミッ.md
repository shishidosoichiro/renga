# retro: 非公開の参考プロジェクト名を公開物の issue とコミットに書いた

# セッション振り返り 2026-10-07

## うまくいったこと

- 取り込み候補を観点別に並行して調べ、候補ごとに推奨と根拠を付けて提示できた
- 指摘を受けてすぐ、すでに書いた範囲を洗い出せた。対象は issue 9件とコミット1件（未 push）

## 失敗・見落とし・やり直し

参考にした非公開プロジェクトの名前を、Renga の公開物に多数書いた。書いた場所は次のとおり。

- 起票した #261〜#267 の本文
- 既存の #194・#228 に追記した節
- コミット `0786767` のメッセージ

名前のほかに、親ディレクトリ起点のパス（`../...`）と、そのプロジェクトの issue 番号も根拠として書いた。

宍戸さんの指摘: 「プライベートなプロジェクトなので、公開するプログラムに書いても誰も意味がわからない」。

### 観測

issue の本文を書くとき、根拠の出典として非公開プロジェクトのパスと issue 番号を書いた。判断記録に出典を残す規約（根拠・出典・見送り理由を issue に書く）に従ったつもりだった。

### そのとき何が見えていたか

- 作業ディレクトリは、非公開プロジェクトの中にある Renga だった。調査の対象はその親ディレクトリだった
- 指示ファイルのどこにも、「親ディレクトリのプロジェクトは非公開で、公開物に書かない」という記述は無かった

### 推測

「出典を残せ」という規約が、出典が非公開かどうかを問わずに適用された可能性がある。公開リポジトリの読み手が辿れる出典かどうかを確かめる手順が無かった。

## 指示ファイルにあればよかったこと

- Renga は公開リポジトリであり、親ディレクトリの非公開プロジェクトの名前・パス・issue 番号を公開物に書かない、という明示
- 判断記録の出典は、公開リポジトリの読み手が辿れるもの（Renga 自身の issue・コード・公開された一次資料）に限る、という条件

## その他気づき

- 外部の運用で得た知見を使うときは、固有名を出さずにユースケースか一般論として書けば、根拠の役目は果たせる
- 対処として、issue 本文の書き直しと、未 push のコミットの amend を行う
