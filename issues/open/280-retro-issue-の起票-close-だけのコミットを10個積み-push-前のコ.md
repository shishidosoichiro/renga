# retro: issue の起票・close だけのコミットを10個積み、push 前のコミットが29個に膨らんだ

## 観測

2026-10-07 のセッションで、push 前のコミットが29個になった。宍戸さんは「なんでそんなにコミットがあるの？」と尋ねた。

内訳は次のとおり。
- `feat` / `fix`: 6
- `docs` / `ci`: 6
- `chore(agent)`: 6
- lint: 1
- issue の起票・close・ラベル付けだけの `chore`: 10

10個のうち多くは、きっかけになったコミットに同梱できた。たとえば次のコミットは、レビューを反映したコミットに含められた。
- b71181c（レビューで出た後続の issue を起票）
- 9902977
- 8142089

## そのとき何が見えていたか

- **読んでいたもの**
  - CONTRIBUTING.md の「1つの論理的な変更を1つの単位に」
  - `/commit` スキルの「feat と fix を混ぜない」「ついでの修正は別の issue・別のコミットにする」
  - リポジトリの過去の慣習（例: `chore: file issue #260 ...` の単独コミット）
- **無かったもの**: 起票だけのコミットを、どこに同梱すべきかの基準

## 推測

「ついでの修正は別コミット」という規則を、「ついでの起票」にまで広げて当てはめた可能性がある。起票は変更の記録であって、コードの修正ではない。きっかけになったコミットに同梱しても、履歴を追う妨げにはならなかった。
